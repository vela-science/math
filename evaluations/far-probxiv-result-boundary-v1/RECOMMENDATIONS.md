# Roadmap disposition

## Adopt now

- Treat FAR as an external discovery and attention-allocation source. Preserve
  exact occurrence locator, source version, observation time, candidate scope,
  and its stage labels as advisory evidence with `authority_effect: none`.
- Keep attempt, machine judgement, formal check, human review, Repository
  Decision, and Standing on separate axes. ProbXiv demonstrates that this is
  already a competitive product baseline, not a Vela-exclusive idea.
- Make known-result and duplicate searches explicit scoped Checks. A found or
  missed duplicate changes the evidence and may motivate a correction; it does
  not itself grant authority.
- Continue using Git and the signed Vela reader as the reconstruction baseline
  for admitted state. Keep external page digests and temporal caveats in
  derived evaluation/source evidence.

## Bounded Web handoff

After this comparison is reviewed, offer the Web owner one narrow contract:
show an external FAR/ProbXiv occurrence on a Problem or Result source panel
with its provider label, exact URL, observed-at time, current source status,
evidence modality, and explicit non-authority caveat. Do not ingest proof/page
bytes, turn a ProbXiv status into Standing, or build a ranking feed.

The public comparison should say that ProbXiv already handles attempt/check
separation and fidelity caveats well. The Vela-specific callout is the path
from a candidate Result to an independently scoped Check, attributed
Repository Decision, Event, Standing, and later correction/readback.

## Later external pilot

Use `EXTERNAL_PILOT.md` first. Only after rights and source custody are clear,
invite one outside evaluator to challenge the matrix and one independent
Repository authority to evaluate a separately prepared Result. The best pilot
is a bounded candidate whose exact source occurrence and evidence can be
published without copying restricted bytes. No candidate in this fixture has
that Vela lifecycle today.

## Monitor

- FAR releases, a durable pilot data export, stable content identities, locked
  environments, and an attributed correction format.
- ProbXiv public API/export, content rights, status-history/duplicate relations,
  and provider-loss reconstruction.
- Quipu's as-of-rule replay and evidence-degradation questions. Revisit only if
  a real Vela Result cannot be answered through exact source observations,
  admitted Events, correction, and Git replay.

## Explicitly rejected

- Problem, Frontier, Attempt, Allocation, Bitemporal, KnowledgeGraph, or Result
  as new Vela Core objects.
- a Vela literature crawler, FAR pipeline, ProbXiv registry, ranking feed,
  graph database, hosted authority, or generic agent runtime.
- flattening FAR scores, ProbXiv labels, Git merges, formal compilation, or
  human-review prose into acceptance or Standing.
- claiming Vela is better at discovery, proof generation, novelty detection,
  or evidence-axis UX. The current evidence does not support those claims.
